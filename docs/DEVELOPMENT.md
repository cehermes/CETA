# CETA 开发文档（给接手的 AI / 开发者）

> 版本：v1.0（数据版本 `VER = 16`）　状态：**功能冻结**，只修 bug、写文档。新需求记入 `CHANGELOG.md` 的"未来迭代"。
> 本文档描述的是 `web/index.html`、`server.py` 的**当前实际行为**，改代码后必须同步更新本文档与 `CHANGELOG.md`。

## 1. 项目概述

CETA（Chicken Eater Trading Assistant，"Chicken Eater" 是作者的网名）是一个本地运行的小工具：用类似 ComfyUI 的**节点工作流**管理股票交易的"计划 → 执行"流程。每个节点是一张卡片，节点里的"参数"可以互相连线；每个节点能把自己的计算结果画成一张 PNG 图片（图片里嵌着整个工作流，拖回页面即可还原），也能存成 JSON 工作流。

- 目标用户：单人、Windows、Chrome/Edge，不懂编程。**不引入任何构建步骤或第三方依赖。**
- 前端：单个文件 `web/index.html`（原生 JS + CSS，无依赖，约 50 KB）。
- 后端：`server.py`（Python 标准库，监听 `127.0.0.1:8199`，被占用则顺延到 8219）。
- 8 个节点：开仓计划 / 开仓执行 / 保本计划 / 保本执行 / 出货计划 / 出货执行 / 加仓计划 / 加仓执行。

## 2. 目录与运行

```
NodeFlow/
├── web/index.html        前端（全部代码）
├── server.py             本地服务
├── start.bat             Windows 启动脚本
├── output/               生成的图片/JSON，按股票代码分子文件夹（不入库）
│   └── <股票代码>/归档/   每个股票文件夹自动建一个"归档"子文件夹，使用者手动归档
├── user/state.json       所有工作流的自动保存（不入库）
├── python_embeded/       可选：Windows embeddable Python（入库的只有 README.txt 说明）
├── examples/             示例工作流（作者编造的数据；PNG/JSON 拖进页面还原，state.json 复制到 user/）
└── docs/ README.md CHANGELOG.md LICENSE
```

`start.bat`：存在 `python_embeded\python.exe` 就用它，否则依次尝试 `python server.py`、`py server.py`。

## 3. server.py 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/`、静态文件 | 提供 `web/` 目录，响应头 `Cache-Control: no-store` |
| GET | `/api/state` | 返回 `user/state.json`（不存在则 `{}`） |
| POST | `/api/state` | 原子写入 `user/state.json`（先写 `.tmp` 再 `os.replace`） |
| POST | `/api/save?path=<股票代码>/<文件名>` | 把请求体原样存到 `output/<股票代码>/<文件名>`，并确保其中有 `归档` 子文件夹；路径每段去掉非法字符，只取前两段 |
| POST | `/api/open` | 用 `os.startfile` 打开 `output` 文件夹（仅 Windows 有效） |

页面直接用 `file://` 打开时不连服务：保存会变成浏览器下载，顶栏显示警告。

## 4. 前端架构（web/index.html）

**全局状态**：`W`（所有工作流标签）、`G`（当前工作流）、`V`（当前视图 x/y/缩放）。工作流 `{nodes, links, uid, dirty, view, h/ht/hp(撤销栈)}`；节点 `{id,type,x,y,v(参数值),ct,mt,col(折叠),c(计算结果)}`；连线 `{a,ak,b,bk}`（a 节点的 ak 参数 → b 节点的 bk 参数）。

**节点定义 `TY`**：每个节点类型一条：
- `f`：可填写参数 `[键, 名称, 默认值, 类型('s'文字/'n'数字，默认n), 显示小数位]`
- `o`：计算结果 `[键, 名称, 小数位]`
- `ord`：行顺序（**必须恰好覆盖 f 与 o 的全部键各一次**）

**其他常量**：`PL` 计划节点类型列表（决定标题圆点配色）；`REC` 蓝点（建议手动输入）参数表；`DEF` 默认连线表；`K`/`TC` 颜色。

**计算 `C[type](v)`**：纯函数，返回
`{title, w(提醒文字数组), vals(结果值), chart(图片描述), tc(标题色), err(错误文案)}`。出错时只返回 `{err}`，节点显示红字且"保存为图片"拒绝执行。开仓两节点共用 `opn`，加仓两节点共用 `adn`（参数 `ex` 区分计划/执行）。

**数据流 `evalG()`**：按连线把上游 `outv(节点,键)`（优先取计算结果 `vals`，否则取输入值 `v`）写入下游参数；重复 `节点数` 轮以收敛，再对每个节点调用 `C`。**接了线的输入变灰只读。** 连线只允许数字↔数字、文字↔文字，且禁止成环。

**时间戳**：`ct` 创建时间；`mt` 最后修改时间，**只有手动改参数或连线传入的值真正变化时才更新**（拖动、传出、重启、拖入图片、撤销到未变状态都不更新）。图片上显示的就是 `mt`，格式 `YYYY年M月D日 周X HH:MM:SS`。

**撤销/重做**：整图快照（`snapStr`），最多 300 步，输入时防抖 500ms 合并；还原时按"参数值是否真的变了"重算 `mt`。

**持久化**：`persist()` 同时写 `localStorage['nf2']` 和 `POST /api/state`（300ms 防抖，`beforeunload` 用 `sendBeacon`）。启动 `boot()` 先读 `/api/state`，再读 localStorage，都没有就建演示工作流 `defWf(true)`。

**保存与拖入**：
- 保存为图片：`card()`→`chartCard()` 画 840 宽 PNG，`tEXt()` 把整个工作流 JSON（`ser()`，非 ASCII 转 `\uXXXX`）写进名为 `workflow` 的 tEXt 块。
- 保存为 JSON：同样内容 `{v:2, focus:节点id, ...sv(G)}`，缩进、UTF-8 可读，不受"输入无效"限制。
- 两者都经 `put()` 上传到 `/api/save`；失败则降级为浏览器下载。保存后清除"未保存"标记。
- 文件名：`<股票代码>_<节点名>_<保存日期YYYYMMDD>_<节点mt的HHMMSS>-<保存时分HHMM>.png|json`。
- 拖入页面：`.json`（或内容以 `{` 开头）直接解析；否则按 PNG 读 tEXt `workflow`。成功则在**新标签**还原；失败提示"这个json文件里没有有效的工作流"/"这张图片里没有工作流信息"。

**其他界面**：多标签、拖动画布、滚轮缩放（0.2–3×）、`Ctrl+Z/Y`、节点折叠（点标题左侧圆点）、双击连线删除、顶栏"＋ 节点"按钮和"打开 output 文件夹"。

## 5. 约定（改代码前必读）

1. **行序对齐**：计划节点与执行节点里**同名参数尽量在同一行号**，这样连线是水平的。可填写=白底，计算结果=灰底；执行节点里"实际成交"类参数是可填写的输入行。调整行序只改 `ord`。
2. **圆点颜色**：可填写行左右各一个圆点（左入右出）；计算结果行只有右侧灰点；数字参数绿点，文字参数（股票名称）黄点；**`REC` 中的参数是蓝点，代表"建议手动输入"**。
3. **图片配色**：目标价洋红（出货类节点里淡化为 `#a86fa8`、常规字重）；止损价红；及格价橙 `#ff8c00`；保本价类绿 `#00ff00`（**虚线=计划/假设，实线=实际**；历史价位用淡绿 `#6fa86f`、常规字重）；当前价白；提醒文字黄 `#fbbf24`，显示在标题右侧（最多 4 行）；执行节点标题浅紫 `#a5b4fc`；日期行显示 `mt`。
4. **数值格式**：百分比 1 位小数；金额取整；股数按 100 股取整（买入向下取整、保本卖出向上取整）；及格价 2 位。
5. **只做被要求的事**：不擅自改参数位置、名称、默认值、颜色。需要替使用者做决定时，要列出来请他确认。
6. **改一个节点时**，必须对比确认其他节点的定义与计算逐字未变。

**公式**（`a`=买入金额，`p`=开仓价，`g`=目标价，`s`=止损价）
- 买入数量 = ⌊a ÷ p ÷ 100⌋ × 100；取整误差 = (1 − 取整后 ÷ 取整前) × 100%
- 及格价 = (p + g) ÷ 2（2 位）
- 盈亏比 = (g − p) ÷ (p − s)；止损% = (p − s) ÷ p；止损金额 = a × (p − s) ÷ p；盈利% = (g − p) ÷ p；盈利金额 = a × (g − p) ÷ p

**校验**：需 `g > p > s` 且买入金额 > 0，否则 `err`。**提醒**：取整误差 ≥ 5%；止损% ≥ 止损%基准；盈利% ≤ 盈利%基准。

**图片**：目标价（洋红，右：盈利）→ 及格价（橙）→ 开仓价（绿**虚线**，右：盈亏比）→ 止损价（红，右：止损）；右下灰字"买入金额 … 买入数量 …"。普通版面。

**公式**（`N`=初始数量，`C0`=初始保本价，`P`=卖出价，`T`=目标保本价）
- 需卖出 x = N × (C0 − T) ÷ (T − P)，必须 x < 0；卖出数量 s = ⌈−x ÷ 100⌉ × 100；卖出后数量 N2 = N − s

**说明**："盈利金额目标"是纯输入行，**不参与计算、不画在图上**，只是用来连线传给下游。

**图片**：卖出价（绿虚线，右：卖出数量/卖出仓位%）→ 初始保本价（绿实线）→ 止损价 → 卖出后保本价（绿虚线，右：卖出后数量/剩余仓位%）→ 及格价（橙）；右下灰字"目标保本价 …"。普通版面。

**公式**（`P`=当前价，`C0`=当前保本价，`S`=止损价，`N`=持仓数量，`IC`=初始保本价，`TG`=目标价，`TP`=盈利金额目标，`PO`=仓位%）
- 浮盈金额 fl = N × (P − C0)；浮盈锁定金额 lk = N × (S − C0)；浮盈锁定率 lr = lk ÷ fl
- 浮盈锁定率基准 = min(100, (P − IC) ÷ (TG − IC) × 100)（`TG > IC` 时；**封顶 100%**）
- 盈利金额目标完成度% = fl ÷ TP（`TP > 0` 时）
- 减仓移损方案（输入：减仓% `B`、移损价 `SS`）：卖出数量 x = min(N, round(N × B ÷ PO ÷ 100) × 100)；执行后剩余 N2 = N − x；卖出后保本价 C2 = (N × C0 − x × P) ÷ N2；盈亏比 = (TG − P) ÷ (P − SS)；执行后锁定金额 = N2 × (SS − C2)；执行后锁定率 = 该金额 ÷ fl；执行后剩余仓位% = PO × N2 ÷ N。x ≥ N 视为全部卖出。

**校验**：需填写当前保本价、`P > C0`、`N > 0`，否则 `err`。**提醒**：减仓% > 仓位%；移损价 < 止损价；执行后锁定率（1 位小数比较）低于基准。
**说明**：参数"初始数量"当前**不参与计算**，只用于连线传给出货执行。

**图片（价格刻度新版面）**：当前价（白，右：浮盈/目标完成度）、止损价（红）、当前保本价（绿，`bk`，右：锁定率/仓位）、目标价（`#a86fa8` 常规，右：盈利金额目标）、及格价（橙）、减仓方案的移损价（红虚线，右：盈亏比）与卖出后保本价（绿虚线，`bk`）；右下灰字为方案说明或缺哪项的提示。

## 8. 数据版本 `VER` 与迁移规则（最重要的纪律）

保存数据带 `ver`。**只要改了任何参数键名、删除/改义了已存档的参数、或改了默认连线，就必须：`VER` +1，并新增 `migrateN(d)`，在 `migrate()` 里加一行 `if(v<N)migrateN(d)`。** `migrateN` 只对旧版本数据运行一次，且**不能让使用者已经删掉的连线重新出现**（补连线前先检查是否已有、且只在"该对节点还有 name 连线"这类证据成立时才补）。

## 9. 价格刻度新版面（`chartOptions.axis = 1`）

用于出货计划、出货执行、加仓计划、加仓执行（保本计划/执行与开仓节点用普通版面，现有案例没有出现明显视觉误差）。解决的问题：保本价可能远低于其他价位（甚至为负数），按比例画会把其他线挤在一起。

**图片整体**：宽 840（`W`）；标题 34px 粗体在 (24,52)；日期 22px 灰在 (24,88)；黑底；线从全宽横线，标签在线上方（左标签 `l`、右标签 `r`，字号 26px，必要时缩小到 16px 以保证 `l+r` 放得下）；提醒最多 4 行，20px 缩到最小 13px，右对齐，从 y=36 起每行 26px。

**普通版面**：所有线按价格从高到低排序，纵向在 y∈[170,620] 线性映射（只有一个价位则全放 170），相邻线最小间距 40；标签位置 = 线位置 − 10。

**新版面算法**：
1. 把线分两类：`bk`（保本价类）与非 `bk`（价格类）。取所有价格类线的最高价 `qH`、最低价 `qL`，价差 `rg = max(qH−qL, |qH|×5%, 0.01)`。
2. **被"冻结"的线**：`bk` 线且价格 < `qL − rg`。其余线（价格类 + 靠近的 `bk` 线）按价格在 [170,620] 内线性映射。
3. 非冻结线的标签位置 = `max(线y − 10, 上一个标签位置 + 28)`（标签至少隔 28px，被推开时在线左侧画一个小折线引导）。
4. 冻结线从最后一条非冻结线的下方 56px 开始，向下每条间隔 46px 排列；线中央画一个锯齿"断线"标记，表示这里不按比例。
5. 底部小字起点 `y0 = max(所有线与标签位置) + 48`，每行 30px，图高 `H = ⌈y0 + 行数×30 + 24⌉`。`footR=1` 时小字右对齐。

线的其他选项：`dash` 虚线、`reg` 常规字重、`alpha` 透明度、`bk` 保本价类。

## 10. 测试方法（沙箱里没有浏览器时）

开发期间用 **Node + 自制最小 DOM 桩**验证逻辑，没有放进仓库（使用者不想装额外软件）。接手的 AI 若要验证，可按下面思路自行重建：

1. 从 `index.html` 取出 `<script>…</script>` 里的代码，在 `vm` 沙箱里运行；沙箱提供桩：`document`（`querySelector` 返回万能 Proxy 元素，`createElement('canvas')` 返回带 `getContext` 的假画布，记录 `fillText`/线段；`toBlob` 返回一个最小合法 PNG）、`localStorage`、`location={protocol:'file:'}`（避免走网络）、`fetch`（记录 `/api/save` 调用）。
2. 在脚本末尾追加一行把内部对象暴露出来：`this.__x={TY,C,DEF,REC,PL,VER,add,upd,fromData,chartCard,save,saveJson,stamp,get G(){return G},get W(){return W}}`。
3. 常用检查：
   - **回归**：用样例存档里的各节点参数，对比"改前/改后"版本的 `C[type](v)` 结果（用键排序后的 JSON 比较），旧节点必须逐项一致。
   - **结构**：每个 `TY[t].ord` 恰好覆盖 `f+o` 的全部键；`DEF` 里的键在 `TY` 中存在。
   - **迁移**：构造低版本数据 `fromData`，检查键、连线、节点数。
   - **往返**：`saveJson`/`save` 的输出再喂给 `document.ondrop`，节点数、连线数不变。
   - **图片**：把假画布记录的绘制指令导出，用 PIL（需 CJK 字体）粗略渲染看版面。
4. 沙箱无法验证：真实字体宽度/缩放、鼠标手感、圆点实际颜色——这些必须请使用者在真实浏览器里看。
